# Horus — новая модель выбора сервера и подключения

Документ для команд **приложения** и **node-агента**. Описывает задумку, что изменилось
в центральном API и как адаптироваться. Актуальная машиночитаемая спецификация —
приложенный `openapi/HorusAPI.json` (регенерируется на каждый `dotnet build`).

> Старую систему (`/servers/best`, старый `/servers/connect` c ответом `{VLESS, HY2}`,
> идентификация пользователя на ноде по e-mail) **удалили целиком** — приложение ещё не
> в проде. Обратной совместимости нет, ориентируйтесь на этот документ.

---

## 1. Задумка

1. **Единый стабильный ID пользователя.** У каждого аккаунта есть `vpn_uuid` — он и есть
   идентичность в VLESS (поле `id` клиента) и метка на ноде. Генерируется один раз, **сам
   никогда не меняется**. Меняется только то, к какому **серверу** он привязан — и только
   когда этого захочет пользователь (или админ при отмене).

2. **Привязка = резервирование места.** Пользователь в любой момент привязан ровно к
   одному узлу (`users.current_server_id`). Каждый узел считает своих привязанных
   пользователей в `vpn_servers.reserved_count`; узел «переполнен», когда
   `reserved_count = max_clients`. Резерв атомарный (`FOR UPDATE SKIP LOCKED`) — два
   параллельных резерва не могут занять одно последнее место.

3. **Покупка подписки резервирует место.** Выдача подписки (admin `PUT …/subscription` —
   это и есть «покупка») сначала резервирует слот. Если свободных мест нет нигде —
   выдача отклоняется (`409 no_capacity`), т.е. **купить подписку при отсутствии мест
   нельзя**. Отмена подписки освобождает слот.

4. **Разделены выбор сервера и подключение:**
   - **выбор** — узнать список кандидатов для TCP-пинга и зарезервировать/сменить узел;
   - **подключение** — быстро отдать готовые ссылки для уже привязанного узла.

5. **Два потребителя `/servers/connect`, разные по формату:**
   - **наше приложение** — сессия в заголовке `X-Session-Key` → JSON, включающий
     **olcRTC** (обход белых списков);
   - **сторонний VPN-клиент** — сессия в query `?key=…` → **base64-подписка** (только
     hysteria2 + все vless узла), которую клиент импортирует как subscription URL.

6. **Генерация ссылок дешёвая.** `/servers/connect` на горячем пути **не ходит на ноду** и
   читает одну строку БД — провижининг ноды делается в момент резерва/выбора, а не на
   каждый connect.

## 2. Идентичность и слоты (БД)

`users`:
- `vpn_uuid UUID` — стабильная идентичность (VLESS id + метка на ноде). Уникальный индекс
  `idx_users_vpn_uuid`. Телеметрия ноды сопоставляет события с пользователем по нему.
- `current_server_id INT` — текущая привязка (зарезервированный слот); `NULL` = не привязан.

`vpn_servers`:
- `reserved_count INT` — сколько пользователей привязано к узлу (**на этом измеряется
  ёмкость**). Управляется центром атомарно.
- `current_load INT` — **живое** число онлайн, которое присылает нода в `/node/events`.
  Для отображения/сортировки, к ёмкости отношения не имеет.
- `max_clients INT` — вместимость.

Доступ (подписка активна): `expires_at IS NULL` (бессрочный — админ/грандфазер) **или**
`expires_at > now()`. Истёкшая подписка (`expires_at` в прошлом) → `403 subscription_expired`.

## 3. Контракт API

Все пути ниже проксируются nginx на API. Аутентификация — прежняя схема: сессия из
`/auth/login` или `/auth/verify` в заголовке `X-Session-Key` (кроме subscription-URL для
сторонних клиентов, см. `/servers/connect`).

### 3.1 `GET /servers` — кандидаты для пинга  · заголовок сессии
Наименее загруженные активные узлы **со свободными местами, по одному на страну**,
отсортированы от наименее загруженных. Клиент их TCP-пингует и выбирает.

```json
[
  { "id": 12, "country": "DE", "city": "Frankfurt",
    "current_load": 3, "reserved_count": 4, "max_clients": 20, "host": "de1.example.com" }
]
```

### 3.2 `POST /servers/select` — зарезервировать / сменить узел · заголовок сессии
Тело: `{ "server_id": 12 }` — конкретный узел; `{}` или `{ "server_id": null }` — автоподбор
наименее загруженного. Переносит привязку (освобождает старый слот, занимает новый) и
пере-провижинит ноды. Идемпотентно, если узел тот же.

- `200` → `{ "id": 12, "name": "Germany 1", "country": "DE", "city": "Frankfurt", "host": "de1.example.com" }`
- `403 subscription_expired` · `404 server_not_found` · `409 no_capacity`

### 3.3 `GET /servers/connect` — ссылки для привязанного узла
Формат ответа определяется **источником сессии**:

**A. Наше приложение — сессия в заголовке `X-Session-Key`** → `application/json`:
```json
{
  "server":   { "id": 12, "name": "Germany 1", "country": "DE", "city": "Frankfurt", "host": "de1.example.com" },
  "vless":    [ "vless://<uuid>@de1.example.com:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=…&fp=randomized&pbk=…&sid=…&type=tcp#Horus-DE%20%C2%B7%20VLESS" ],
  "hysteria2":  "hysteria2://<uuid>@de1.example.com:8443,20000-30000/?sni=de1.example.com&obfs=salamander&obfs-password=…#Horus-DE%20%C2%B7%20HY2",
  "olcrtc":   { "provider": "…", "transport": "…", "room_id": "…", "room_key": "…", "uuid": "<uuid>", "host": "de1.example.com" }
}
```
`vless` — массив (сейчас один вариант, дальше — все виды на узле). `olcrtc` = `null`, если
узел не анонсировал комнату. **olcRTC отдаётся только здесь** (приложению).

**B. Сторонний VPN-клиент — сессия в query `?key=<session>`** → `text/plain`, **base64** от
списка ссылок через `\n` (все vless + hysteria2, **без olcRTC**). Это subscription URL:
```
GET https://<domain>/servers/connect?key=<session>
→ dmxlc3M6Ly8uLi4KaHlzdGVyaWEyOi8vLi4u        (base64)
   ├ vless://<uuid>@…#Horus-DE · VLESS
   └ hysteria2://<uuid>@…#Horus-DE · HY2
```

Общие коды: `401` (нет/неверная сессия) · `403 subscription_expired` · `409 no_capacity`.
Если пользователь ещё не привязан — connect привяжет его автоподбором (и один раз
провижинит ноду); дальше connect уже к ноде не ходит.

### 3.4 Подписка / резерв (admin)
- `PUT /admin/users/{username}/subscription` `{ "expires_at": "…" }` — **выдать/продлить**.
  Сначала резервирует слот; при отсутствии мест → `409 no_capacity` (подписка не выдана).
- `DELETE /admin/users/{username}/subscription` — **отменить**: снять срок, освободить слот,
  снять пользователя с ноды.

## 4. Контракт node-агента

Общее: HTTPS, заголовок `X-API-PASSWORD` = `vpn_servers.auth_password`. Порт управляющего
канала — `Nodes:ControlPort` (по умолчанию `8444`), схема — `Nodes:Scheme` (по умолчанию
`https`).

### 4.1 Центр → нода (управление пользователями) — **изменилось: ключ теперь `vpn_uuid`**
- `POST  {scheme}://{host}:{ControlPort}/users`  тело `{ "uuid": "<guid>" }`
  → добавить пользователя в inbound `clients` (id = uuid, email/label = uuid). **Идемпотентно.**
- `DELETE {scheme}://{host}:{ControlPort}/users/{uuid}` → удалить. **Идемпотентно.**

Раньше слали `{ email, uuid }` и удаляли по e-mail — **больше не делаем**. Идентичность
везде — `vpn_uuid`.

### 4.2 Нода → центр
- `POST /node/register` — **без изменений**: нода сообщает `reality_*`, `olcrtc_*`, порты,
  `agent_version`. Значения `olcrtc_*` центр отдаёт приложению в `/servers/connect`.
- `POST /node/events` — телеметрия. **Событие теперь идентифицирует пользователя по `uuid`:**
  ```json
  { "provisioned_count": 40, "online_count": 12,
    "events": [ { "uuid": "<guid>", "type": "disconnect", "reason": "timeout", "at": "…" } ] }
  ```
  `online_count` → `vpn_servers.current_load`. `events` необязательны; `reason` пишется в
  `users.last_disconnect_reason` (по `uuid`).

### 4.3 Обязанности ноды
- **Персистить свой набор пользователей и реконсайлить xray из него при рестарте.** Центр
  НЕ пере-провижинит на каждый connect — он провижинит в момент резерва/выбора и полагается
  на то, что нода восстановит `clients` из своего хранилища.
- Держать актуальными olcRTC-параметры комнаты (для обхода белых списков нашим приложением).

## 5. Что делать команде приложения

1. **Идентичность:** ничего не генерировать — `vpn_uuid` уже на сервере; всё завязано на него.
2. **Выбор сервера:** `GET /servers` → TCP-пинг кандидатов → `POST /servers/select {server_id}`.
   Автоподбор — `POST /servers/select {}`.
3. **Подключение:** `GET /servers/connect` с `X-Session-Key`. Приоритет — `olcrtc` (обход
   белых списков); при отсутствии/недоступности — `vless[…]` / `hysteria2`.
4. **Смена страны/сервера:** снова `select`, привязка переедет (место на новом узле должно
   быть свободно, иначе `409`).
5. **Подписка для сторонних клиентов (по желанию):** дать пользователю subscription URL
   `https://<domain>/servers/connect?key=<session>` — импортируется в v2rayN/Hiddify/Streisand.
   Помните: ключ в URL чувствителен — «Выйти на других устройствах» его инвалидирует.

## 6. Что делать команде node-агента

1. Управляющие ручки: `POST /users {uuid}`, `DELETE /users/{uuid}` (идемпотентные, ключ — uuid).
2. Телеметрия `/node/events`: слать `uuid` в событиях и честный `online_count`.
3. Персист + реконсайл `clients` из своего стора при рестарте.
4. `/node/register` — как раньше, плюс держать `olcrtc_*` в актуальном состоянии.

## 7. Изменения схемы БД (`init.sql`)
- `vpn_servers.reserved_count INT NOT NULL DEFAULT 0` (+ бэкофилл из текущих привязок).
- `vpn_servers.current_load` — теперь именно живой онлайн из телеметрии.
- `users.vpn_uuid` — бэкофилл для старых строк, `NOT NULL`, уникальный индекс `idx_users_vpn_uuid`.
- Индекс подбора `idx_servers_available (country, reserved_count) WHERE is_active`.

`init.sql` применяется только при инициализации пустого тома. На существующей БД
идемпотентные `ALTER/UPDATE` из нижней секции нужно прогнать вручную (они безопасны к
повторному запуску).

## 8. Заметки и открытые вопросы
- **Ключ сессии в URL** (subscription для сторонних клиентов) виден прокси/логам — это плата
  за совместимость. Ротация: `/auth/logout-others`.
- **Истёкшая подписка держит слот** до отмены/переезда — так привязка остаётся стабильной, и
  продление возвращает тот же сервер. Массовые «мёртвые» резервы освобождаются отменой
  (admin `DELETE …/subscription`).
- **Дедлайн-эджкейсы переезда** (двусторонняя блокировка двух узлов) крайне редки; при
  конфликте транзакция откатится и клиент получит `503` — повторить запрос.
